# 相机方向与像素坐标

手部相机 `end_camera` 位于 `grip_base_link` 局部坐标 `(0.066, 0, 0.040)`，视场角 50°。相对原安装高度仅沿 TCP **+Z** 下移，朝向不变。相机光轴平行于 TCP（`ee_frame`）的 **+X**，画面上方为 TCP **+Z**，画面右方为 TCP **−Y**。相机保留安装位置偏移，因此光轴与 TCP 前进方向夹角为零，但两个原点不重合。TCP 原点对标夹爪闭合时的指尖位置，不是相机光心，也不是张开时的指尖。该高度使闭合夹爪的指尖进入画面底部，张开时指尖仍可能在视野外。

MuJoCo 相机局部 −Z 是观察方向，+Y 是画面上方，因此模型使用 `xyaxes="0 -1 0 0 0 1"`。该关系随机械臂运动保持不变。原相机网格已替换为悬空黑色长方体，位于光心后方，仅作视觉标识，不参与碰撞。

## RGB-D 与反投影

三路相机均输出 RGB PNG 与 uint16 毫米深度 PNG。深度表示沿光轴的距离，不是到相机原点的欧氏距离；0 表示无效深度。背景、非有限值、裁剪范围外和超出 uint16 可表达范围的深度均置零。关闭离屏多重采样，使深度对应像素中心，避免子像素深度采样引入反投影偏差。

`POST /v1/camera/point` 必须指定 `camera`、`pixel` 和该像素的 `depth_m`。默认服务端内参及外参用于反投影；省略 TCP 位姿时，`end` 使用当前 TCP 位姿，`opposite` 和 `left` 使用各自固定相机位姿。可传入 `tcp_position_base` 与 `tcp_quaternion_base` 指定 TCP 位姿，必须成对提供。也可提供图像响应头中的全套采集元数据（TCP 位姿、相机相对 TCP 外参和内参），按该帧的标定精确反投影；这一路径不读取当前 TCP 状态或服务端图像。返回坐标为 `base_link` 下 XYZ（米）。选择当前姿态意味着坐标按请求处理时的状态计算，并不保证与更早获取的深度帧同步。越界像素或无效深度返回 `INVALID_ARGUMENT`。

`GET /v1/camera/image` 返回的图像响应头包含 base64url 编码的采集时 TCP pose、相机相对 TCP 外参和内参。`end`、`opposite` 和 `left` 均可用，结果为 `base_link` 下 XYZ（米）；无效深度不应提交。

CLI 的 `image point` 需要将同一张 depth 图中的采样值、采集位姿、相机外参和内参通过 `--request-json` 传入 `/v1/camera/point` 请求体。

## 固定桌对面相机

`opposite`（模型名 `opposite_camera`）位于机械臂前方、桌子对面，固定于 `base_link` 相对坐标 `[0.939, 0, 0.439]` 米；默认 world 坐标为 `[0.939, 0, 0.689]`。镜头朝基座方向，以 45° 俯角看向操作区域中心（base `[0.55, 0, 0.05]`，即 world `[0.55, 0, 0.30]`）。相对原位置只沿原光轴拉近，朝向和 60° 垂直视场角不变。方块、绿色放置目标区及机械臂操作高度仍在画面内；更外侧的潜在操作区（base 下 X 为 0.35–0.70 米、Y 为 ±0.25 米、Z 至 0.30 米）不再保证全部入画。相机到桌面观察中心的距离约为 0.55 米。光心后方的悬空黑色长方体表示相机外壳，不参与碰撞。HTTP、CLI 和 agent 工具均使用 `opposite` 选择该相机。三路相机通过共享快照提供最新已发布图像，依次渲染。

```bash
mujoco_cli image get --camera opposite --output artifacts/opposite.png
```

## 左侧固定相机

`left`（模型名 `left_camera`）固定于 `base_link` 相对坐标 `[0.55, 0.55, 0.35]` 米，在机械臂左侧看向操作区中心（base `[0.55, 0, 0.08]`）。垂直视场角为 60°，到观察中心约 0.61 米。它与 `opposite` 一样不随机械臂运动；省略 TCP 位姿做反投影时使用该相机采集帧的固定外参。光心后方的悬空黑色长方体不参与碰撞。

```bash
mujoco_cli image get --camera left --output artifacts/left.png
```
